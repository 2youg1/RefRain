按版本推进，不给日期。每条只说做什么、以及怎样算做完。

**欢迎提功能建议**。开一个 issue，讲清你当时想写什么、软件在哪里挡了你。讲情境比讲

## v0.2.2 — 前端重做与 Windows 实测（已发布）

**前端完全重做。** 界面层推倒重来，把这一年积下的形状问题一次改掉：

- 单侧栏场所：文档树、发送信箱（待发送/未读/已处理，未读带徽标，已处理可回溯）、
  栏脚统一入口；栏顶搜索精确/模糊可切，Ctrl+F 直达
- 提案在原文锚点右缘落印点，点开就地裁决（饭盒）：原文划线、提案可改、
  接受/改后接受/退回，不再跳全屏
- 发送台是全屏半透明表面，正文在下面虚化可读；右键工作区只记录不打断
- KARA 是顶部 20% 的渐透明滤镜，不是逐行聚焦；Ctrl+Enter 与栏脚按钮两个入口
- 排版全部滑杆实时渲染；动效进场减速、离场加速，任何等待帧都有连续运动
- 多智能体编排落地：×1/并行/接力/校验四种边，接力与校验的请求里真的有上游产出
- 工程面：死代码总清（TS 与 Rust 两侧）、44 道门禁钉住这些形状

**Windows 实测。** 本仓库现有的每个数字都出自 Linux。WebView2 真实窗口、输入法行为、
安装路径、高刷新率屏幕、从按键到出字的全链路——在 Windows 上测过之前，任何性能声称都
默认只对 Linux 成立。

*做完的判据*：Windows 上有一份与 Linux 同口径的实测数据，且四道检查在该平台全绿。

*实际状况*：三平台 CI 矩阵已经在跑，Windows 与 macOS 各 56 道门禁只红
`verify:editor-performance` 一道（mount p95 分别为 53.40ms 与 143.00ms），
是共享 runner 的抖动，不是功能缺陷。但**这仍然不是作者自己机器上的数据**：
WebView2 真实窗口、输入法、高刷新率屏幕、从按键到出字的全链路都还没有人亲手测过。
安装包因此挂着「未完成，请勿下载」的标记，直到作者在自己的 Windows 上实测并同意撤下。

## v0.2.3 — 渲染端排版（已发布）

**核心是 Markdown 在渲染端的排版。** 中英日混排的作者每天都在手工对付这些事：

- 全角半角全文一键切换（代码、URL、数字与拉丁文中的标点不受影响）
- 多语言混排的空白间距，按视重平均而不是插入固定宽度的空格
- 标点挤压，规则随语言预设走——日文与中文的挤压规则本就不同
- 禁则与断行严格度，分宽松、标准、严格三档
- 标点悬挂，让版心右缘在视觉上齐整
- 编辑时的格式高亮辅助，轻到不与正文争夺注意力

间距与挤压都在渲染时施加，不写进文本：磁盘上的 `.md` 是唯一正本，作者没打的空格不
应该出现在他的文件里。

以上全部落地，断行走自研实现而不是浏览器的 `text-wrap`；为什么这样选、代价是什么，
见 [ARCHITECTURE](ARCHITECTURE.md) 的「Why RefRain breaks its own lines」。

语法高亮的内嵌语言从 8 种扩到 **34 种**（原计划约 30），按「在手稿里出现得起」取舍，
不求覆盖。整组配置与运维格式 gzip 后仅 17,894 字节。

**HTML 的特殊处理**：HTML 要么以资料形式呈现，要么拉起真实浏览器渲染。不在编辑器内
自造一个半吊子渲染引擎——那既不准确，也会把「零出网」这条不变量的边界搅浑。

**没有做的那一半。** 原计划里「新增可编辑的文件类型，原生兼容，不经转换中间层」
这张表**没有落地，顺延到后续版本**。仓库今天的实际能力是单向的：

| 格式 | 今天能做什么 | 距离「可编辑」还差什么 |
|---|---|---|
| DOCX、PPTX、XLSX、EPUB | 导入为文本（`extract_*`） | 没有任何写回路径 |
| 文字版 PDF | 只渲染，永不写回（是有意的取舍） | 按设计不会变成可编辑 |
| LaTeX | 仅语法高亮 | 没有解析与往返 |

把这件事记在这里而不是悄悄删掉：判据要求「保存回原格式并核对往返」，而单向导入
不满足它。

*做完的判据*：一份含代码块、URL、中英日混排的真实手稿，执行全文全半角切换后除正文
标点外零改动，且一次撤销可还原；禁则三档在同一段文本上产生可见不同的断行；每种新
格式都能打开、编辑、保存回原格式并核对往返，不能无损往返的必须在打开时说明会丢什么。

*达成情况*：前两项达成（`verify:layout-parity` 等门禁钉住）；第三项未达成，见上表。

## v0.2.4 — 原生多格式编辑与日常修补

承接 v0.2.3 未完成的那张表。目标不变：**原生兼容，不经转换中间层**。

| 类别 | 格式 | 达成 |
|---|---|---|
| 文档 | LaTeX | 打开、编辑、保存回原格式，存储层逐字节核对往返 |
| 代码 | TypeScript、Rust、Python、Go、Lean 4 | 同上；按扩展名走 Native SDK 的 code 部件高亮（SDK 17 门 lexer，RefRain 映射 9 门；LaTeX/Lean/TOML 不上色也不套近似语法） |
| 样式与标记 | CSS、HTML、XML | 同上；HTML 仅源码编辑，不渲染（按设计） |
| 配置 | TOML、YAML | 同上 |
| 文档 | DOCX | 不做：抽取实测丢 90.4% 字节，没有诚实的写回路径 |

文字版 PDF 不在此列：它按设计只渲染不写回。

非 Markdown 文档按行分块、不做 Markdown 结构解析、搜索索引不剥行内标记。
断行分流（P3.7）：代码格式走等宽硬切（`typeset::line_starts_code`，无禁则
无行尾调整），Markdown 与 LaTeX 走散文断行（禁则与候选）——LaTeX 是写作
格式，中文注释与公式文字按散文排。Markdown 路径的行为逐字节不变
（`verify:layout-parity`、`verify:byte-invariance` 钉住）。

**同版落地的日常修补**（每条都有定位与测试）：

- **撤销与历史**：编辑器不再拒绝 Ctrl+Z；每个动作进 `text_actions` 历史表，
  重启后仍可撤销（深度 64 步）；侧栏「历史」面板可选择性回档到任意一步——
  其后 N 步一并撤回。携带裁决的动作拒绝被普通撤销跨过（账本不说谎）；
  对判决本身的反悔走邮箱的「冲销合并」：append-only 的逆向裁决，
  批量一次动作、一次撤销可还原。
- **链接与伙伴**：连接在 CLI 升级搬家后沿 PATH 自愈（同一 id，真重验证）；
  不可达时显示「上次可用版本」而非逼你重连；退出键入页眉；伙伴原地编辑
  （此前「编辑」永远在追加新 id）；身份说明回显。
- **协议装载**：一键把生成的协议装进 harness 的 skill 目录并校验摘要；
  已装的连接首轮请求只带一行协议路径，不再内嵌全文。
- **Agent 工作区**：每个伙伴有持久工作区（`.refrain/agents/<id>/`），身份以
  AGENTS.md 随工作目录自动加载；Memo.md 由伙伴自维护；接续轮在请求开头
  明文标记「无完整上下文，先全文读 Memo.md」。
- **设置与排版**：面板宽度拖边缘手调并持久化；设置页在窄面板不再塌陷
  （容器查询）；排版滑杆可拖可输数值；默认行宽 65em；字体直接列出本机
  全部家族。
- **搜索**：「精确/模糊」开关的显示修复（此前切换生效但标签永不变——
  一个漏了 memo 的 prop）；UI 路径补 Exact→Loose 回退。
- **标点**：右键菜单只列选区内的转换项；数字间的 `。` 不再误转；
  「转换全文标点」接上菜单（一次动作，一次撤销可还原）。
- **表格**：列间竖线在视觉上连续（纯 CSS，零字节改动）。
- **资料**：右键可移入回收站、可调整范围（仅大纲/可检索/全文），
  下一次派发即生效。
- **邮箱**：独立管理页（置顶/弃置/取回/批量），侧栏只留缩略与徽标。
- **性能**：导入的 HTML 资料打开从数秒降到亚秒——排版度量从 O(n×r)
  修为 O(n+r)（40 万字符实测 5570ms → 512ms），外加视口带延后排版。
- **真实产出容忍**：harness 的 CLI 爱在产出前叙述一句。恰好一个根元素时
  裁剪叙述（元素本身仍按冻结请求逐项校验）；零个或多个根保持具名拒绝。
  实测全流程（真窗口 + 真 Kimi Code + 真模型）：连接→伙伴→批注→派发→
  产出→提案渲染→裁决→合并→保存，全链通过；接力与校验两种边也各有
  真窗口用例。

*做完的判据*：每种纯文本格式都能打开、编辑、保存回原格式并核对往返
（已达成）；DOCX 如实标注不做。Windows 真机实测口径同 v0.2.2 一节——
安装包继续挂「未完成，请勿下载」直到作者实测。

## v0.2.5 — 原生重写与智能体互动创作（已发布）

**这一版做两件事，先后有序。**

**一、界面迁到原生渲染路径。** 旧的 Tauri + WebView + SolidJS 表面整体删除
（27,175 行），换成 Native SDK 的原生渲染（2,691 行手写源码）。交付的二进制里
没有 WebView，也没有 JavaScript 运行时。Rust 领域层、持久化与智能体运行系统
原样保留——产品规则从来不在界面里，所以它们一条都没丢。

换栈的理由不是「原生更好听」，而是两条实测：断行必须自研（被替代的引擎只认
空格和制表符，中文段落两样都没有），以及旧前端的缺陷成因是七份会话状态与
156 处界面局部状态之间的订阅、epoch、取消与回调传递——逐页照搬只会换一种语法
保留同一批成因。

*做完的判据*：最终安装包只含一个正式界面，不保留隐藏的 WebView 备用路径；
10 万块、11.4 MiB 正文能打开、编辑、滚动、选择、保存与恢复；应用进程不联网；
只有人类裁决能把智能体的提案写进正文。

**二、智能体互动创作。** 现有的编排层已经能让多个智能体在一轮里并列、承接、
校验；这一版把它推到创作场景：角色、长期设定、多轮互动，而裁决权仍然在人手里。

*做完的判据*：一次多角色、多轮的创作会话可以完整跑通并保存，而每一段进入正文的
文字都留有裁决记录。

*当前状况*：已发布。发布前门禁 31 道全过、Rust 569 条测试全过、原生表面通过
严格检查，且 9 道门禁各自被注入验证过「能因正确的理由变红」。发布时尚未做的：
角色二态（Work／Cosplay）与连续接力的界面部分——前者已在 v0.3.0 补上（设置页的
Agent 名录），后者仍待接；Windows 与 macOS 的输入法链路代码写好了，但没有在真机
上签字。

## v0.3.0 — 原生表面的其余屏幕与 Windows 构建

承接 v0.2.5「一个去处一屏」的未竟部分，并把 Windows 构建修到真机可用。

**这一版接上的屏幕**（每条都从 Rust 的既有机制接出来，不在界面里新写规则）：

- **历史与回档**：原生编辑保存同步进 `text_actions`；「历史」面板逐行列出，
  点一步即回档（其后 N 步一并撤回）。协议新增 `RevertTo`（code 14）。
- **信箱**：全部文档的提案与作者的安排合成一屏（草稿/未读/已处理），置顶、
  弃置、取回，已处理可**冲销**——逆向裁决 append-only。信箱合成在
  `refrain-app/src/mailbox.rs`，ReviewTask 不进列表（理由在模块注释）。
- **冲销落盘**：修掉一个真缺口——此前冲销只改内存与账本，不写磁盘，正是
  F-01 那个分裂的反向。现在冲销与合并共用同一个写者 `persist_manuscript`，
  走同一个 compare-and-swap；外部改动以 `Conflict` 交还（D1 双向成立）。
- **批注面板**：高亮与评论的读取（写入仍待接）。
- **搜索跳块**：点一条命中直接跳到当前文档里的那一块；跨文档跳块未接。
- **角色二态开关**：设置页列出 Agent 名录，干活 ↔ 扮演一键切换，身份原文
  由 Rust 带过去；无身份的 Agent 按钮灰掉（Rust 侧本是 no-op）。
- **字体**：Antic Didone（拉丁）与 Zen Kaku Gothic New（日文）补回，与
  Noto Sans SC 三张注册进渲染器。如实标注：SDK 排印只有全局正体/等宽两个槽，
  逐字回退不存在，正稿由 Noto Sans SC 一张画出。

**Windows 构建修复**（都是实测发现的真问题）：补 `ole32` 与 zig libunwind
链接；`runtimeobject.def` 改绑 `combase.dll`（剪裁版 Windows 没有 RuntimeObject.dll
这个转发库，而符号的真身一直在 combase）；给 Native SDK 的 coff 后端打一个
`bun patch` 固化的补丁（Windows 下跳过 analysis obj 合并）。

**已知边界，如实标注**：排版设置在原生端落盘生效，但渲染还不消费排版值
（字号/行长不进投影）；批注只有读取；连续接力的界面未做；Effect 在本仓库
仍然没有消费者（见 docs/EFFECT.md 的 territory 表——这不是文档落后，是
消费者随旧界面删除，是否引入新消费者留待裁决）。

*做完的判据*：门禁全过、Rust 测试全过、原生测试全过；作者在真机上实测
通过后发布，并提供 Windows 客户端。

**v0.3.0 第二波（2026-08，原生表面完备化）**：

- **Native SDK 0.7.2 → 0.8.1**：TS core 换到官方外部核心编译器（check 与
  build 同一裁决），transpiler 通道随官方删除而退役；补丁集重放固化——
  其中「SDK 断不了中文」（换行搜索只认空格/制表）是「前端不如 v0.2.4」
  的最大单因，已用 hard_breaks 补丁把 Rust 的禁则行首接进编辑器布局。

  投影（设置滑杆实时预览）；材料草稿成稿与一键提拔正文；跨文档跳块；
  锚定区间进投影（提案印点 + 就地裁决饭盒）。
- **v0.2.4 交互完整回迁**：裁决键盘流（Alt 族）、印点+饭盒、派发深度
  （块清单/攒段/资料分区/带稿三档/委托/预览→授权两步/Run 名录与在飞
  轮询）、120ms 防抖搜索与命中摘录、命令表唯一权威（按钮/菜单/快捷键

  `material.zig` 配方表 + SDK 原生 `backdrop_blur`，面板/饭盒/回来卡/

- **多 Agent 发射通路**：`ProjectInput::LaunchRun` + 派发台/信箱双台

- **审计修复**：手动往返在有具名伙伴时不可达（哨兵修复）；选区派发丢
  委托/带稿/资料三闸（并线进 `dispatchDesk`，删 `dispatchScope` 等
  ~124 行死写器）；预览 digest 被任意答复冲掉（专槽）；编辑 Agent 参数
  抹掉手绑连接（回填修复）；超 12KB 请求的「死按钮」（灰掉并说原因）；
  删除无生产者的 `project_facts` 臂与零调用方的 `intBytes`。
- **动效收编**：`motion.zig` 唯一权威（时长/easing/循环形状），veil 与

## v0.3.1 — Run runner 与承接项

**头条：Run runner（M9）**。让原生 app 真正跑起多轮多 Agent：发射已
授权的 Run → 调 harness 适配器起进程 → observe 收流 → 落 `result.md` →
`CompleteDispatch`。域层与全部测试都按它存在来写（`adapters.rs` 的
dispatch/observe、工作区布局、`CompleteDispatch`），缺的就是这个运行时
本体。顺带接上两个被它挡住的消费者：校验者批注（`AgentComment` 已解析、
收取时被丢）与下游孤儿清理（上游失败/取消后下游的具名交代，而不是
永远等待）。

## 已经在做但不属于某一版

**原生界面的其余屏幕。** 领域层已经完备并带测试——就地渲染、表格、图、PDF 阅读——
缺的是原生表面。它们按「一个去处一屏」逐个接上，共用同一份名录与游标规则，而不是
每屏各写一套。历史、批注、搜索跳块、信箱、排版渲染消费、连续接力（下游自动发射与
LaunchRun）已在 v0.3.0 接上；PDF 与图是下一批。

**块级命中。已完成。** 命中带上那句话的上下文，点一条直接跳到文件里的那一块
而不只是那个文件。

**精度作为可见选项。已完成。** 搜索默认精确（Exact），可切模糊（Loose）。
二到五字的常见查询下两者结果仍多雷同，但开关是可见的，分歧一旦出现作者自己
就能看见。

## 不打算做的事

**云同步服务。** 手稿是你硬盘上的一堆 Markdown 文件。你已经信任的任何同步工具都能处理
它们，没有一个需要这个软件帮忙。

**账号体系。** 没有东西可登录。应用进程不发起任何网络请求，而给它一个联网的理由，代价
是丢掉那条让其余一切站得住的不变量。

**成为格式本身。** RefRain 读写别的工具也能读的 Markdown 文件，不会引入一个你日后必须
从中导出的私有容器。

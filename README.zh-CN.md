# Recension

**一个本地写作工作台：Agent 的每一次落笔都是你可以否决的提案，而你的否决本身是数据。**

*[English README](README.md)*

---

*Recension*——校勘：比对多个抄本的异文，给出理由，判定何者成立。多个版本送到面前，由一个人裁决，裁决被记录下来，日后可以被质疑。

这就是产品的全部。

## 你为什么要用它

先说它拒绝做什么。

**它不会写进你的正文。** Agent 产出的是提案，人点击才合并。没有自动接受、没有后台合并、没有 YOLO 模式，也没有任何设置、参数或插件能造出一个。如果你曾让 Agent 跑过一整章，然后花一小时找它悄悄改了什么——这个项目存在的全部理由就在这里。

**它不会向外发一个字节。** 应用进程无出站网络请求。无账号、无遥测、无自动更新、无崩溃上报。所有模型调用发生在你自己的 Harness 里，用你自己的凭据。你可以用防火墙验证这句话——这正是它被这样写出来的原因。

**它不会替你算账。** 没有价格、没有成本预测、没有「你已用掉预算的 40%」。token 数如实回传 Harness 上报值，标注 `actual`、`estimated` 或 `unknown`。Harness 报不出来，你看到的就是「未知」，而不是一个看起来很合理的零。

**它不会花你没批准的 token。** 没有后台摘要、没有自动上下文补全、没有「贴心的」预取。每一次调用都出现在你批准的清单里才发出，也绝不为了替你省钱而擅自裁剪。

**它不会绑架你的稿子。** Markdown 落盘，离开这个应用依然可读、可改、可 git。明天把软件删了，你的稿子完好无损、一字未动。

**Agent 全部离线时它照常工作。** 所有 Harness 断开，它仍是一个完整的写作软件：打开、编辑、搜索、保存、撤销。

这些拒绝之后剩下的，是一个把 Agent 的提议原样摆在你面前的工作台——你可以接受、改写，或者带着理由扔掉，而理由会被记住。

## 核心：裁决账本

Agent 直接写进你的文件。你看一眼 diff，接受或还原。然后理由就蒸发了——你为什么否掉那一段、那句话哪里不对、这个人物的语气你到底要哪一版。下一次它再犯同样的错，你再改一遍。

所有工具都把你的判断当成一次性界面事件。点了接受，事就没了。

Recension 把它留下。每一次判断——接受、拒绝、改后接受，以及**为什么**——都是一等公民数据。这一个改动带来三件事：

**它会回话。** 你的裁决成为下一轮 Prompt 的一部分。Agent 用你自己的话、锚在具体段落上，读到上一版为什么不行。

**它会累积。** 几百条裁决就是你判断文字的样本。不训练、不微调，只是检索你自己记录下来的口味。

**它能作证。** 一部完成的稿子可以显示：哪一句是你写的，哪一句是 Agent 提议的，哪一句是 Agent 提议而你重写的。

编辑器会过时，Harness 每年换一批。你的判断记录不会。

## 它不是 Harness，而是 Harness 之上的编排层

Recension 不跑模型，也不拥有 agent loop。它驱动你已经在用的 Harness，而它的野心在更上一层：**人与多个 Agent 之间、以及 Agent 彼此之间的协作编排。**

大多数 Harness 给你一个对话、一个 Agent。真实的工作不长这样。Recension 把它建模成一张图——任务扇出到多个竞争的 Agent，结果收敛到唯一的人类决策点，而这个决策成为下一轮的输入。

- **竞争提案。** 同一段广播给多个 Agent，然后择一、综合，或者全部否掉。
- **跨会话对白。** 两个会话各持一个角色，工作台居中传话若干轮，整段交锋作为一条提案送审。
- **攒批派发。** 跨章节、跨 Agent 攒好队列，审阅合并清单，一次发出。
- **每一条边都由人把关。** 没有点击就没有下一轮。没有任何自主循环能够到达你的正文。

首发面向长篇散文与小说。这套编排模型并不限于文字，编程场景会随后跟上。

## 工作流程

```
正常写作
  → 选一段、写 Prompt、挑 Agent
  → 加入队列，想攒多少攒多少
  → 一次点击发送
  → 你的 Harness 执行并写出结果文件
  → Recension 冻结为不可变的提案
  → 你逐条裁决，附上理由
  → 你的决定原子地提交到正文
  → 裁决进入账本
```

## Harness 支持

适配器按 Harness **能证明什么**分级，而不是按它声称什么。

| 台阶 | 要求 | 你能得到 |
|---|---|---|
| **L0** | 无——Agent 写一个文件即可 | 任何 Harness 立刻可用，含手动复制粘贴 |
| **L1** | 可程序化启动会话、收完成事件、可取消 | 派发、取消、实时状态 |
| **L2** | 如实上报 usage、可回读实际模型、有压缩事件 | 真实 token 数，可信的上下文预警 |

| Harness | 台阶 |
|---|---|
| [Codex](https://github.com/openai/codex) | L2 |
| [Claude Code](https://code.claude.com/docs) | L2 |
| [Pi](https://pi.dev) | L2 |
| [Kimi Code](https://moonshotai.github.io/kimi-code/) | L2 |
| [Hermes](https://hermes-agent.nousresearch.com/docs) | L1+ |

能力不足从不是拒绝，而是降级加如实标注。写一个 L0 适配器只需几十行。**欢迎贡献，这份清单本就是为生长而设的。**

## 它从哪里来

同一作者的两个在先项目，都还在运行：

**[md2prompt](https://github.com/kaile9/md2prompt)**——单文件 HTML 编辑器，记录人的每一处修改，导出协议精确的 `Prompt.md` 供 Agent 读取。它验证了要紧的那一半：人的修改与批注，序列化成 Agent 无需调用工具、无需重传原文就能消费的格式。Recension 把方向反转过来——Agent 提议，人裁决——并保留了让原作成立的那份协议纪律。

**[apostle-skills](https://github.com/kaile9/apostle-skills)**——用于严肃阅读、研究、翻译与长程工作的 Agent Skills。其中两本直接塑造了本设计。`apostle-artifacts-loops` 贡献了委托纪律：一次性标识符、重试不覆盖、以磁盘工件作为彼此看不见的 Agent 之间的会合点。`apostle-constitutio` 贡献了双向零信任，它成为这条规则：工作台从不采信 Agent 的自我报告，只认磁盘上经过校验的文件。

## 现状

早期开发中。[`SPEC.md`](SPEC.md) 是唯一权威设计基准，[`ROADMAP.md`](ROADMAP.md) 说明范围与明确不做的事，[`AGENTS.md`](AGENTS.md) 是贡献者（人或 Agent）的工作契约。

技术栈：TypeScript、Bun、Electron、Svelte、ProseMirror。
